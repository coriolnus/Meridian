## Global Constraints
- Sır sızmaz: FMP/bot anahtarları yanıt gövdesine, git'e, log çıktısına ASLA; `$env://`
  referansları serbest. FMP anahtarı sorgu parametresinde kalıyorsa kapı access-log'unda
  görünmemesi ölçülür (görünüyorsa rota-bazında log kapatılır — etiket maskeleme DEĞİL).
- 402 ≠ 429: kapı hiçbir durum kodunu yutmaz/çevirmez; adapter'ın 402-rotasyon mantığı
  BOZULMADAN geçer (canary ⑧). Kapının KENDİ kota reddi 429 + ayırt edilebilir gövde.
- Tek kaynak: rotalar/tüketiciler yalnız routes.yaml'dan; elle Admin CRUD kalıcı değil.
- Uydurma yasağı: her canary ÖLÇÜLÜR (şema teyidi `GET /apisix/admin/schema/plugins/<ad>`
  config yazımından önce — ROADMAP şartı).
- Motor değişikliği (fmp.py) TDD + tam suite hükmünden önce push YOK (§8).
- `plugins:` listesi varsayılanı EZER: her rotada kullanılan her plugin açık yazılır
  (prometheus dahil — 2026-09-01 vakası).

### Task F2-A: `fmp-veri` rotası (config, Rol-1)

**Files:** Modify `deploy/apisix/routes.yaml` · apply A1'de `ops/apisix_uygula.py --uygula`

Rota: `uri: /fmp/*` → upstream `financialmodelingprep.com:443` (https, TLS doğrulama —
canary ⑤: `tls.verify`/`nginx proxy_ssl_verify` hangisi 3.18'de geçerliyse ölçülüp o yazılır).
Plugins: `prometheus: {}` · `proxy-rewrite` (regex_uri: `^/fmp/(.*)` → `/stable/$1`; host
başlığı upstream'e) · `limit-count` (count 250, time_window 86400, policy redis
127.0.0.1:6379, key_type var, key remote_addr DEĞİL — rota-geneli sabit anahtar; rejected_code
429, rejected_msg "kapi-fmp-gunluk-kota").

**Adımlar:** şema teyidi (limit-count + proxy-rewrite) → routes.yaml düzenle → apply →
`--denetle` drift boş → CANARY: (1) A1'den gerçek anahtar sorgu-parametresiyle küçük istek
(`/fmp/quote?symbol=AAPL`) 200 + gövde doğru; (2) durum-kodu geçirgenliği: bozuk anahtarla
401/402 sınıfı NE dönüyorsa AYNEN istemciye ulaşıyor; (3) access-log'da apikey görünüyor mu
(görünüyorsa rota log kapatma); (4) prometheus'ta `route="fmp-veri"` satırı doğdu; (5) Kapı
sayfası `faz2_fmp` rozeti "canlı"ya döndü (limit-count imzası).

### Task F3-A: TLS dinleyici + sertifika + pano rotası (operatör talimatı 2026-09-01: Faz 3 TAM yapılır)

**Zemin ölçümleri (yazmadan önce):** apisix-kapi konteynerinin ağ modu (bridge ise host'a

**Kurulum sırası (güvenlik sırası — kimliksiz yüzey ASLA internete çıkmaz):**
1. Geçici sertifika: self-signed (CN=A1 IP; alan adı gelince certbot + Admin API push'a geçilir
   — sabah karar sorusu: "alan adın var mı / alayım mı?"). Sertifika Admin API `/ssls`e yüklenir;
   ANAHTAR git'e girmez (A1-yerel üretilir).
2. `pano-ingress` rotası: uri `/*` (host eşlemesiz v1) → upstream host:8080; plugins:
   `key-auth` (pano-operator tüketicisi) + `limit-req` (kaba: 10 r/s burst 20) + `client-control`
   (max_body) + `prometheus` — uri-blocker/request-validation ilk soak'tan sonra sıkılır.
   NOT: pano'nun kendi parola kapısı AYNEN kalır — key-auth ÜSTÜNE gelir (çift kapı bilinçli).
3. APISIX TLS 9443'ü dinler (config.yaml + konteyner port eşlemesi gerekiyorsa yeniden-yaratma).
4. Yerelden ölçüm: `curl -k https://127.0.0.1:9443` key'siz 401 · key'le pano HTML'i.
5. DIŞ AÇILIŞ EN SON ve yalnız 4 yeşilken: OCI güvenlik listesi 443 (A1'de `oci` CLI varsa
   Rol-1; yoksa operatöre konsol adımı) + host güvenlik duvarı. Açılış sonrası dıştan ölçüm.
